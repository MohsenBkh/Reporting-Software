# ReportForge — گزارش‌یار مطالعات

تولید خودکار گزارش مطالعات فنی اتصال مصارف سنگین (۱ مگاوات و بالاتر) به شبکه توزیع —
مطابق دستورالعمل TAV111-10/00 شرکت توانیر و ساختار دفترچه‌های مطالعات شرکت توزیع نیروی برق استان اردبیل.

## تازه در نسخه 1.1.0 — Rule Engine مطالعه مصارف سنگین

- **خروجی استاندارد Rule**: هر قاعده یک نتیجه با ساختار
  `rule_id / category / status / input_values / calculated_values / finding / evidence /
  source / source_page / recommended_text / engineer_review_required` تولید می‌کند
  (Machine-readable + متن مهندسی فارسی).
- **۵۶ Rule تحلیلی + ۳ Rule تولید سناریو** استخراج‌شده از دفترچه مطالعات (TAV111-10/00) در ۸ حوزه:
  تقاضا، ایستگاه‌های نزدیک، خطوط نزدیک، متقاضیان همزمان، توپولوژی تأمین مشترک، سناریو،
  بررسی اقتصادی و کنترل ناسازگاری داده‌ها.
- **محاسبه صریح Delta = After − Before** و تفکیک «افت ولتاژ مطلق» از «تغییر ناشی از متقاضی».
- **تولید سناریو بدون توصیه**: Scenario 1 (فیدر جدید) و Scenario 2 (فیدر موجود/جایگزین) با ثبت
  Technical Basis / Required Network Changes / Candidate Feeder / Estimated Cost /
  Required Equipment / Supporting Evidence / Review Status — انتخاب نهایی فقط با مهندس.
- **بررسی اقتصادی پارامتریک**: پارامترهای هزینه در تنظیمات (خارج از کد)؛ نبود هزینه = `MISSING_DATA`
- **ورود داده در برنامه**: صفحه «مطالعه مصارف سنگین» در Sidebar (۵ جدول: تقاضا، ایستگاه‌ها، خطوط،
  متقاضیان همزمان، مسیر/هزینه سناریوها) + تب تنظیمات «حدآستانه‌ها» و «پارامترهای هزینه» — بدون
  نیاز به ویرایش دستی `project.json`. جدول‌ها اسکرول‌دار، با فضای دینامیکی و امکان **حذف/بازگرداندن ستون**.
  (هرگز صفر) و اقلام مستثنی به‌صورت شفاف فهرست می‌شوند.
- **کنترل ناسازگاری داده (DATA_INCONSISTENCY)**: مغایرت مجموع افزایش بار با کل بار گزارش‌شده و
  مغایرت تقاضای درخواستی با تقاضای مبنای تحلیل → `REQUIRES_ENGINEER_REVIEW` بدون حدس یا جایگزینی.
- **MISSING_RULE به‌جای آستانه اختراعی**: هر Rule آستانه‌های موردنیازش را اعلام می‌کند؛ اگر آستانه
  در سند/پیکربندی نباشد، هیچ داوری‌ای انجام و هیچ متنی تولید نمی‌شود.
- هفت بخش جدید در گزارش Word/پیش‌نمایش (فقط در صورت وجود داده مطالعه)؛ پروژه‌های بدون داده مطالعه
  دقیقاً مثل v1.0.3 تولید می‌شوند.

مستند کامل Rule Set: `docs/STUDY_RULE_SET_v1.1.0.md` — بازتولید با `python tools/export_rule_set.py`.

## تازه در نسخه 1.0.3

- رابط کاربری حرفه‌ای: Sidebar، نوار مراحل Workflow، داشبورد، Theme روشن/تاریک، آیکن‌های یکپارچه، StatusBar.
- اعتبارسنجی هوشمند (واحد، محدوده منطقی، داده ناقص) با راهنمای رفع و پرش به محل مشکل.
- تفکیک «ولتاژ مطلق» از «اثر متقاضی»؛ افزایش تلفات به‌تنهایی مبنای اقدام اصلاحی نیست.
- کنترل کیفیت پیش‌بینی (R²، Outlier، جهش/مانور، داده ناقص) با وضعیت REQUIRES_ENGINEER_REVIEW.
- بازبینی مهندس: Accept / Edit / Reject / Override / Comment با ذخیره دائمی.
- ردیابی منبع هر داده (Excel / CSV / دستی / محاسبه / PowerFactory) + پیوست‌های گزارش.
- Word بهبودیافته: «صفحه X از Y»، جلد بدون شماره، TOC، Caption Style، تکرار سرستون جدول.
- تولید گزارش در Thread پس‌زمینه با Progress؛ خطاها فارسی و بدون Traceback (Log در پوشه کاربر).

جزئیات: `CHANGELOG.md` و `TEST_REPORT.md`.

## ویژگی‌ها

- **حداقل ورودی، حداکثر تولید**: کاربر فقط اطلاعات اصلی را وارد می‌کند؛ متن، جداول، شکل‌ها، شماره‌گذاری و فهرست مطالب خودکار تولید می‌شود.
- **چارچوب گزارش مطابق نمونه‌های واقعی**: مقدمه ← تحلیل بارگذاری فیدرها ← پیش‌بینی ۵ ساله ← نتایج پخش بار قبل ← نتایج پس از اعمال بار ← جمع‌بندی.
- **موتور قواعد مهندسی (Rule Engine)** با قواعد قابل ویرایش در JSON:
  - ولتاژ: محدوده مجاز (پیش‌فرض 0.95–1.05 p.u.) و سقف تغییر ۵٪ طبق دستورالعمل اتصال مصارف سنگین
  - تشخیص «افت ولتاژ موجود ≠ ناشی از بار جدید» (منطق گزارش ناب پروتئین)
  - طبقه‌بندی بارگذاری فیدر (کم‌بار / عادی / نسبتاً پربار / پربار / بحرانی)
  - جریان نسبت به ظرفیت هدایتی و هشدار افزایش تلفات
- **کتابخانه متن فارسی** (64 متن قالب در JSON) دقیقاً با ادبیات گزارش‌های مرجع — قابل ویرایش توسط کاربر.
- **تحلیل پروفیل بار**: ورود از Excel/CSV یا Paste — پیک سالانه، تاریخ پیک، ضریب توان در پیک، نمودار P/Q.
- **پیش‌بینی ۵ ساله**: رگرسیون خطی روی پیک‌های سالانه با R²؛ اگر داده کافی نباشد **هیچ عدد ساختگی تولید نمی‌شود** (اصل NEVER INVENT ENGINEERING DATA).
- **تحلیل خودکار Before/After**: ΔI، ΔLoss، ΔV و درصدها.
- **پشتیبانی چندفیدری**: ساختار گزارش و جداول خودکار با تعداد فیدر تنظیم می‌شود.
- **مانور/بازآرایی شبکه** (اختیاری) با ثبت عدم قطعیت‌ها.
- **خروجی Word فارسی RTL**: سربرگ، پاورقی با شماره صفحه، فهرست مطالب (فیلد TOC)، جداول راست‌به‌چپ، کپشن شکل/جدول.
- **ویرایش متن توسط کارشناس**: متن هر بخش قابل ویرایش است و هنگام تولید مجدد حفظ می‌شود.
- **تولید سریع از Excel**: یک فایل قالب استاندارد → پروژه کامل → اولین نسخه گزارش در چند دقیقه.
- **Auto Save** و پرسش ذخیره هنگام بستن.

## ساخت فایل اجرایی (exe) — ویندوز

```bat
build_exe.bat
```

خروجی: `dist\ReportForge.exe` (onefile، بدون کنسول). پس از ساخت، خودآزمون به‌صورت
خودکار اجرا می‌شود و گزارش `dist\ReportForge-smoke.txt` در کنسول نمایش داده می‌شود.

بررسی دستی سلامت exe:

```bat
dist\ReportForge.exe --smoke-test
type dist\ReportForge-smoke.txt
```

ساخت نسخهٔ اشکال‌زدایی (با کنسول، برای دیدن متن خطاها):

```bat
set REPORTFORGE_SPEC_CONSOLE=1
build_exe.bat
```

> **توصیه:** برای ساخت exe از Python 3.12.4+ یا 3.13 استفاده کنید. در 3.12.0–3.12.3 یک باگ
> در `importlib` وجود دارد که باید در سطح بسته‌بندی جبران شود؛ این جبران در
> `app/pyi_rth_reportforge.py` + `app/utils/import_guard.py` پیاده شده است (نیازمند افزودن
> `runtime_hooks` در `ReportForge.spec` که انجام شده است). جزئیات: `docs/EXE_BUILD_FIX_v1.1.2.md`.

## قالب Excel استاندارد (تولید سریع)

از صفحه اصلی → «قالب Excel ورودی». شیت‌ها:

| شیت | محتوا |
|---|---|
| پروژه | اطلاعات پایه (نام متقاضی، نوع درخواست، توان‌ها، پست، امور، مانور، ...) |
| فیدرها | نام فیدر، پست، پیک MW، سال، ضریب توان، جریان‌ها، معیار بارگذاری |
| پخش بار | نتایج قبل/بعد هر فیدر (جریان، تلفات، ولتاژها) |
| پروفیل بار | Date / Feeder / P_MW / Q_MVAR |
| پیش‌بینی | پیش‌بینی دستی (اختیاری): فیدر، سال، پیک |

سپس صفحه اصلی → «تولید سریع از Excel».

## تست

```bat
python -m pytest tests
```

سه سناریوی الزامی سند طراحی:
1. تأمین برق جدید ۱۵۰۰ کیلووات، ۱ فیدر
2. افزایش قدرت ۱۰۰۰→۱۱۰۰ کیلووات، ۲ فیدر + مانور
3. مشکل ولتاژ موجود (قبل خارج از محدوده، بعد بدون تغییر) → تشخیص «ناشی از افزایش قدرت نیست»

## اصول طراحی

- SIMPLE FOR ENGINEER — POWERFUL UNDER THE HOOD
- هیچ Thresholdی Hard-Code نیست — همه از تنظیمات/قواعد JSON
- هیچ داده مهندسی‌ای ساخته نمی‌شود؛ داده نبود = پیام شفاف
- متن گزارش فقط از داده + قواعد تعریف‌شده تولید می‌شود
